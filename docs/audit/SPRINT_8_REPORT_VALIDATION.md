### 2. Defect Remediation: CSV Formula Injection Protection (CWE-1236)

#### 2.1 Discovered Defect
During Sprint 8 reporting audits, `export_scans_csv()` in `app.py` was inspected:
- Raw scan target URLs, finding titles, and WHOIS strings were written directly into `csv.writer` without sanitization.
- If a monitored asset had a title or finding starting with `=`, `+`, `-`, or `@` (e.g. `=cmd|'/C calc'!A0`), spreadsheet applications (Microsoft Excel, LibreOffice Calc) could execute it as a formula upon opening the CSV file.

#### 2.2 Remediation Applied
In `app.py` (`export_scans_csv`), imported `_sanitize_cell` from `reports/generator.py` and applied it across all string values:
```python
writer.writerow([
    _sanitize_cell(str(s.id)),
    _sanitize_cell(str(s.target_url)),
    _sanitize_cell(str(s.whois_info or "N/A")),
    _sanitize_cell(str(wp_ver or "Unknown")),
    plugins,
    _sanitize_cell(findings_str),
    s.score if s.score is not None else "N/A",
    s.grade or "N/A",
    s.status.value if hasattr(s.status, "value") else str(s.status),
    _sanitize_cell(str(s.started_at))
])
```
Any string beginning with `=`, `+`, `-`, `@`, `\t`, or `\r` is safely prefixed with a single quote (`'`), rendering it as inert text in spreadsheet software.
